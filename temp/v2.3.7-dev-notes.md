# v2.3.7-dev — Gateway 重启命令修复（服务端准备脚本）

## 这版修的是什么

上一版（v2.3.6-dev）的服务端准备脚本把 Gateway 彻底搞挂了：脚本**先无条件 kill 掉在跑的 gateway**，再用 `hermes gateway run --host 0.0.0.0` 重启——但 `gateway run` **不接受 `--host` 参数**（报 `unrecognized arguments`），于是「杀了却起不来」，22122 端口彻底失联，Buddy 诊断显示 LLM 和 Gateway 双双「端口未监听」。

## 修复内容（server-bootstrap.js）

1. **新增统一重启函数 `gw_restart()`**：
   - 有 systemd 单元 → `systemctl restart hermes-gateway`；
   - Gateway 在跑 → `hermes gateway restart`（失败回落 `stop` + `run`）；
   - Gateway 没跑 → 直接 `hermes gateway run`；
   - 没有 hermes 命令 → `python3 -m hermes_cli.main gateway run`。
2. **彻底移除 `--host` 参数**：绑定地址由 config.yaml 的 `host:` 决定（脚本第 3 步已确认 `0.0.0.0`）。
3. **删掉盲杀循环**：不再"先 kill 再说"，避免重启失败导致服务失联。
4. 第 7 步仅在**刚写入过 API_SERVER_KEY** 时才再重启一次（ENV_WRITTEN 标志），不再无条件重复重启。
5. **最终核验**：脚本结尾确认端口监听，仍未监听时自动 dump gateway.log 末尾 30 行帮助定位。

## 升级后操作

1. 安装本版本；
2. 连接页点「生成服务端准备脚本」，复制到 Hermes 主机以 root 执行——**新脚本会把挂掉的 Gateway 重新拉起来**；
3. 看到「最终核验 OK：端口 22122（Gateway + LLM）正在监听」即成功；
4. 回 Buddy 点「探测」，LLM 与 Gateway 应显示可达。
