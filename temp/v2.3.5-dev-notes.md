## v2.3.5-dev — 服务端准备脚本修复（LLM 自动启动不再瞎猜命令）

### 问题
v2.3.4-dev 的「生成服务端准备脚本」在 LLM（8800）未监听时，写死尝试了 `hermes api_server run`，但该子命令在她的mes CLI 中并不存在，导致：
- 自动启动失败；
- 只打印两条猜的命令，不显示真实报错，无法定位。

同时确认 `setup-server.py` 部署流程本就**没有**启动 8800 的 LLM router 这一步，所以全新安装后 8800 也不会自己起来。

### 修复
- 重写了 bootstrap 脚本第 4 步 `ensure_llm_running`：
  - 先用 `hermes --help`（或 `python3 -m hermes_cli.main --help`）**自动枚举子命令**，并把清单打印出来；
  - 在候选子命令（api_server / llm / serve / router / model / server）里逐个验证 `--help` 真实存在，再尝试 `run` / 无动词 启动；
  - 启动失败时**把 `api_server.log` 的真实报错和完整子命令清单打印出来**，方便定位真正的启动方式。
- 修复 `set -euo pipefail` 下两个会导致脚本提前中断的隐患：
  - `hermes --help` 管道加 `|| true`；
  - `ensure_llm_running` 调用加 `|| echo`，即使 LLM 没起来也会继续打印 API Key 和完成提示。
- 同步修正 `docs/WINDOWS_CLIENT.md` 中那条已失效的 `hermes api_server run` 说明。

### 测试全链路
请安装本版本后，在 Buddy 连接页点「生成服务端准备脚本」，复制到 Hermes 主机（192.168.0.231）以 root 执行。
- 若 LLM 子命令在候选列表里 → 脚本会自动把它拉起，8800 出现监听即成功；
- 若脚本仍没拉起 8800 → 它会打印 `hermes --help` 全量子命令 + `api_server.log` 真实报错，把那段输出发我即可精确定位。
