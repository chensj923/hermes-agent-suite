# v2.3.8-dev — 端点能力探测：自动区分"服务端 agent 端点"与"纯推理端点"

## 根因（实测确认）

v2.3.6/2.3.7 里 Gateway `:22122/v1/chat/completions` 虽然能连通，但它是 **Hermes 服务端 agent 端点**（api_server 平台）。对它发带 tools 的请求实测发现：

1. **无视请求里的 tools**（返回 `tool_calls: null`）；
2. **注入约 1.2 万 token 的自有系统提示**（一句 "hi" 的请求 `prompt_tokens: 12178`）；
3. **在服务器本地执行命令**（回复内容是服务器 `/root` 的真实目录清单）。

所以 Buddy 里出现：模型自称"工作目录是 /root"、右侧执行记录永远是空的（命令根本不在 Windows 上跑）、对话内容重复。Buddy 需要的是**无状态纯推理端点**——`hermes proxy`（默认 8800），它才支持标准 OpenAI function calling。

## 修复内容

1. **`brain.js` 新增 `probeCapability()`**：连接时发一个最小 FC 请求判别端点类型——
   - 有 `tool_calls` → 无状态纯推理端点（Buddy 适用）；
   - 无 `tool_calls` 且 `prompt_tokens` 被注入（>2000）→ 服务端 agent 端点（Buddy 不适用）。
2. **`session-manager.js` 新增 `resolveBrain()`**：connect/resume 时自动探测；
   若是 agent 端点，自动尝试同主机 8800/8000 纯推理端口并**自动切换 + 持久化 + UI 提示**；
   全都找不到则给出可操作的错误（提示启动 `hermes proxy`）。
3. **服务端准备脚本第 4 步重写**：用同样的 prompt_tokens 判别法探测 8800/8000；
   没有就自动启动 `hermes proxy`（先打印 `hermes proxy --help` 定位参数，再尝试 `run`），
   成功后把 Buddy 的 LLM 地址指向 proxy 端口。
4. 文档订正（WINDOWS_CLIENT.md 端口约定）与测试补齐（含"agent 端点自动切换"回归测试）。
5. 全量测试 **77/77 通过**。

## 升级后操作

1. 安装本版本，重开 Buddy；
2. 连接时如果原来填的是 22122，Buddy 会自动探测并提示"已切换到纯推理端点 http://…:8800/…"；
3. 若 8800 上没有 proxy，请先用新版「生成服务端准备脚本」在服务器执行一次（它会自动启动 hermes proxy），再重连。
